# 챗봇 골든 질문 회귀 테스트

실제 챗봇에 질문을 던져 답이 맞는지 자동 채점한다. **pytest가 아니다** — Gemini를 진짜로
부르므로 CI가 아니라 배포 전에 손으로 돌린다.

```bash
python -m evals.run_golden
```

## 왜 필요한가

기존 테스트는 전부 **배선**만 본다.

| 테스트 | 잡는 것 |
|---|---|
| `tests/test_agent_prompt_format.py` | 프롬프트 자리표시자 누락으로 대화가 전멸하는 사고 |
| `tests/test_agent_tool_coverage.py` | 도구를 만들고 편성에 넣는 걸 잊어 영영 못 부르는 사고 |
| 각 서비스 단위 테스트 | 함수가 숫자를 맞게 계산하는가 |

아무도 안 보던 것이 하나 있다 — **모델이 올바른 도구를, 올바른 인자로 부르는가.**

8/4 사고가 정확히 거기서 났다. 챗봇이 "어제 매출 얼마야?"에 `get_sales_history(days=1)`을
넣었는데 그 인자는 "지금부터 24시간 전"이라, 오후에 물으면 어제 낮 매출이 통째로 빠진다.
그래서 "판매 내역이 없다"고 답했다. 함수도 도구 등록도 프롬프트도 멀쩡했고 **모든 테스트가
통과했다.** 사장님만 틀린 답을 들었다.

## 무엇을 잡는가

### 1. 골든 대조 — 이미 아는 오답의 재발

정답을 계산할 수 있는 질문. `golden.yaml`에 숫자를 박지 않고 **무엇을 계산하면 정답인가**만
적는다(`sales_total(day=yesterday)`). 데모 시드는 매시간 크론이 새로 만들기 때문에 숫자를
박아 두면 한 시간 뒤 전부 실패한다. 러너가 채점하는 순간 `truth.py`가 DB에서 실제 값을 뽑는다.

### 2. 감시 규칙 — 정답을 몰라도 걸리는 이상 (`checks.py`)

**새로운 유형의 오답은 여기서 드러난다.** 골든 대조는 적어 둔 질문에서만 동작하지만, 실제로
터진 사고들은 대부분 "질문이 무엇이든 일어나면 안 되는 일"이었다.

| 규칙 | 등급 | 잡는 것 |
|---|---|---|
| 무근거숫자 | 실패 | 도구를 하나도 안 부르고 금액을 답함 — 가장 강한 환각 신호 |
| 마크다운노출 | 실패 | `**`·백틱이 답변에 남음 (채팅 화면에 그대로 보인다) |
| 내부값노출 | 실패 | `total_revenue` 같은 영문 키·JSON 조각·매장 이메일 노출 |
| 거절 | 실패/경고 | "지원하지 않는 기능" — 담당 전문가가 있는데 거절하면 라우팅 실패 |
| 표현불일치 | 실패 | 같은 뜻 두 표현이 서로 다른 금액을 답함 (정답을 몰라도 버그 확정) |
| 근거없는금액 | 경고 | 답변의 금액이 도구 출력 어디에도 없음 (모델이 계산한 값일 수도) |
| 지연·빈답 | 실패/경고 | 40초 초과, 빈 답변 |

실패는 통과율에서 깎고, 경고는 사람이 보라고 표시만 한다 — 오탐이 섞이는 규칙을 실패로
잡으면 리포트가 헛경보로 덮여 아무도 안 보게 된다.

### 3. 탐색 문항

정답을 모르는 질문(`탐색:` 절)에도 감시 규칙은 그대로 적용된다. 정답을 정의할 수 없는
영역(리포트·예측·상권·마케팅)의 새 오답을 발굴하는 자리다.

## 사용법

```bash
python -m evals.run_golden                      # 전부 (약 50턴, 시간·한도 많이 씀)
python -m evals.run_golden --golden-only        # 정답 대조 문항만
python -m evals.run_golden --only 매출,지출      # 분류로 고르기
python -m evals.run_golden --id sales_yesterday # 문항 하나만
python -m evals.run_golden --pace 20            # 429가 잦으면 간격을 늘린다
python -m evals.run_golden --json out.json      # 이력 비교용 저장
```

종료 코드는 실패 문항이 있으면 1, 없으면 0이다.

### 무료 한도 주의

모델별 **분당 15회** 제한이 있고, 한 턴이 메인+서브에이전트로 여러 번 호출한다. 즉 실제
상한은 분당 서너 턴이다. 러너는 429를 만나면 35초 쉬었다 두 번까지 다시 묻고, 그래도
안 되면 그 질문을 **채점에서 제외**한다(가짜 실패로 잡지 않는다). 일일 한도가 소진되면
남은 문항을 오답으로 기록하지 않고 즉시 중단한다.

## 세트가 스스로 자란다 — 자동 수확

사고가 났을 때 사람이 질문을 파일에 추가해 줄 거라는 전제는 현실적이지 않다. 그래서 운영
대화를 자동으로 감시해 사고를 잡고, 재현 검증을 거쳐 세트에 등록한다.

```
운영 대화
   ↓  app/services/ai/answer_audit.py — 매 턴 감시 규칙 + 사장님 부정 반응 감지
사고 후보 (chat_incidents 테이블, status=pending)
   ↓  python -m evals.harvest — 평가 매장에서 같은 질문을 2번 다시 물어 재현 확인
golden.auto.yaml 에 문항 등록 (status=registered) / 재현 안 되면 기각(rejected)
   ↓
다음 run_golden부터 함께 돈다
```

### 감지 (`answer_audit`)

- **감시 규칙** — 위 표의 fail 등급이 그대로 운영에도 적용된다
- **사장님 부정 반응** — 답을 받고 "아니야 어제 팔았잖아", "틀렸어", "왜 없다고 해?" 같은
  발화가 오면 **직전 턴**을 후보로 올린다. 숫자가 그럴듯하게 틀린 오답은 감시 규칙이 못
  잡고, 그걸 아는 사람은 사장님뿐이다. 8/4 사고도 그런 대화에서 드러났다.

정상 턴에서는 정규식만 돌고 끝난다 — **LLM 호출 0회, DB 접근 0회**. 규칙을 어긴 턴에서만
한 번 기록하므로 대화 응답 시간에 영향이 없다.

같은 매장의 같은 질문·같은 규칙은 행을 늘리지 않고 `hits`만 올린다.

### 검증·등록 (`harvest.py`)

```bash
python -m evals.harvest --dry-run     # 판정만
python -m evals.harvest --limit 5     # 5건까지 재현하고 등록
```

두 번 물어 한 번이라도 같은 규칙을 다시 어겨야 등록한다. 검증 없이 등록하면 감시 규칙의
오탐과 일시적 장애(분당 한도·외부 API 실패)가 그대로 문항이 되고, 세트가 쓰레기로 차면
통과율이 의미를 잃는다. 일일 한도가 소진되면 후보 상태를 건드리지 않고 멈춘다 — 여기서
기각으로 찍으면 진짜 버그가 조용히 세트에서 빠진다.

사람이 직접 확정/기각하려면 `GET /chatbot/incidents`, `PATCH /chatbot/incidents/{id}`.

### 자동 등록의 경계 (정직하게)

- **감시 규칙형 사고는 완전 자동이다.** 규칙은 모든 답변에 자동 적용되므로 질문만 등록해
  두면 재발 시 다시 잡힌다.
- **'사장님부정'형은 완전 자동이 안 된다.** 무엇이 정답인지 기계는 모른다. 질문만 등록하고
  통과 조건은 비워 두며, 파일에 `# TODO` 주석을 남긴다. 사람이 나중에 `정답:` 한 줄을
  채우면 그때부터 정답 대조 문항이 된다.
- **개인정보는 메일·전화·주민번호만 가린다**(`mask_personal`). 질문에 적힌 **사람 이름은
  못 가린다** — `golden.auto.yaml`은 저장소에 커밋되는 파일이므로, 등록된 문항을 한 번씩
  훑어보는 것이 좋다.

## 문항 직접 추가하기

`golden.yaml`은 사람이 쓰는 파일, `golden.auto.yaml`은 harvest가 쌓는 파일이다. 섞으면
손댈 문항을 찾기 어렵고 통째로 되돌리기도 힘들어서 나눠 두었다.

```yaml
- id: sales_yesterday
  분류: 매출
  질문:                        # 같은 뜻 2~3표현 — 하나만 맞는 건 우연일 수 있다
    - "어제 매출 얼마야?"
    - "어제 얼마 팔았어"
  정답: sales_total(day=yesterday)   # truth.py의 계산기
  데이터질문: true              # 매장 데이터를 물었나 (무근거숫자 규칙의 대상)
  통과:
    도구: [get_sales_history]
    전문가: [data_expert]
    금지문구: ["기록이 없"]
```

쓸 수 있는 정답 계산기는 `truth.CALCULATORS`에 있다. 새 계산기가 필요하면 `truth.py`에
함수를 추가하고 그 dict에 등록하면 된다.

문항 파일의 오타(없는 계산기·없는 전문가 이름·id 중복)는 `tests/test_golden_suite.py`가
**API 호출 없이** 잡으므로 CI에서 매번 돈다. 채점 규칙 자체의 회귀도 같은 파일에서 본다.

## 한계

적어 둔 질문에 대한 회귀와, 감시 규칙이 아는 유형만 잡는다. 감시 규칙에 없는 새로운
실패 양식은 사람이 발견해서 규칙으로 옮겨야 한다.
